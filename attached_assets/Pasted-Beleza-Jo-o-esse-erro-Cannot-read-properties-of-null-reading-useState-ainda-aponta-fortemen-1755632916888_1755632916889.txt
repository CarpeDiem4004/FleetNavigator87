# Hotfix: "Cannot read properties of null (reading 'useState')" no Vite/React

## 0) TL;DR (ordem exata)
1. **Remover duplicatas** e alinhar versões  
2. **Forçar dedupe/alias no Vite**  
3. **Conferir tsconfig JSX**  
4. **Garantir que não existe outro `react` no root/servidor**  
5. **Limpar e reinstalar**

---

## 1) Alinhar dependências (client/)
Edite `client/package.json` para garantir versões **iguais** e únicas:

```json
{
  "dependencies": {
    "react": "18.3.1",
    "react-dom": "18.3.1"
  },
  "resolutions": {
    "react": "18.3.1",
    "react-dom": "18.3.1"
  }
}

Se usar pnpm ou yarn, as resolutions ajudam a forçar a versão única.
Se houver package.json no root e outro em client/, mantenha react só em client/.

Comandos (na pasta client/):

npm uninstall react react-dom
npm i react@18.3.1 react-dom@18.3.1
npm dedupe
npm ls react react-dom

O npm ls deve mostrar apenas uma instância de cada.

⸻

2) Vite: dedupe + alias para a cópia local

Edite client/vite.config.ts:

import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import path from 'path'

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: {
      react: path.resolve(__dirname, 'node_modules/react'),
      'react-dom': path.resolve(__dirname, 'node_modules/react-dom')
    },
    dedupe: ['react', 'react-dom']
  },
  server: {
    // opcional: mantém overlay ligado, mas é útil para ver o erro
    hmr: { overlay: true }
  }
})

Isso evita que vite/monorepo/links peguem outra cópia de react fora do client/.

⸻

3) tsconfig com JSX moderno

Verifique client/tsconfig.json:

{
  "compilerOptions": {
    "jsx": "react-jsx",
    "moduleResolution": "bundler",
    "esModuleInterop": true,
    "skipLibCheck": true,
    "target": "ES2020",
    "module": "ESNext"
  }
}

Importante: usar "jsx": "react-jsx". Se estiver como "react", o build pode tentar usar React.* direto e causar import/resolução esquisita.

6) Conferências rápidas
	•	Sem <script src="https://unpkg.com/react..."> no index.html. React deve vir só do bundler.
	•	Sem preact/compat mapeando react em alias (a menos que seja proposital).
	•	useFetchWithAuth e qualquer outro hook:
	•	Declarado como função começando com use*.
	•	Usado apenas dentro de componentes funcionais (ou outros hooks), no topo (sem if/for/condicional).
	•	Ex.: const { data } = useFetchWithAuth(...); dentro do componente.

7) Versão segura do useFetchWithAuth

Opcional, mas aqui está o hook estável (coloque em client/src/hooks/useFetchWithAuth.ts):

import { useEffect, useState } from 'react'

type Options = RequestInit & { skip?: boolean }
type State<T> = { data: T | null; error: Error | null; loading: boolean }

export function useFetchWithAuth<T = unknown>(
  url: string,
  token: string,
  options: Options = {}
): State<T> {
  const [state, setState] = useState<State<T>>({
    data: null,
    error: null,
    loading: !options.skip,
  })

  useEffect(() => {
    if (options.skip) return
    let cancelled = false

    ;(async () => {
      setState(s => ({ ...s, loading: true, error: null }))
      try {
        const resp = await fetch(url, {
          ...options,
          headers: {
            'Content-Type': 'application/json',
            Authorization: `Bearer ${token}`,
            ...(options.headers || {}),
          },
        })
        if (!resp.ok) throw new Error(`Request failed: ${resp.status}`)
        const json = (await resp.json()) as T
        if (!cancelled) setState({ data: json, error: null, loading: false })
      } catch (e) {
        if (!cancelled) {
          setState({ data: null, error: e instanceof Error ? e : new Error('Unknown error'), loading: false })
        }
      }
    })()

    return () => {
      cancelled = true
    }
  // ⚠️ Use apenas chaves estáveis nas deps:
  }, [url, token]) // se precisar, controle 'options' fora e passe sinalizadores simples

  return state
}

Dica: evitar JSON.stringify(options) nas deps para não re-renderizar infinito; controle flags simples (ex.: reloadKey) no componente.
