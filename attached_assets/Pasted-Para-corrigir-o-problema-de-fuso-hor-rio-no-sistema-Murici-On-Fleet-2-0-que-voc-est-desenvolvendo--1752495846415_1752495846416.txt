Para corrigir o problema de fuso horário no sistema Murici On Fleet 2.0 que você está desenvolvendo no Replit (frontend + backend com Supabase), o ideal é centralizar o tratamento de horário em UTC no backend e ajustar a conversão para o fuso local (ex: América/São_Paulo) apenas no frontend quando for exibir para o usuário.

Aqui vai um passo a passo completo para corrigir isso em todo o sistema, tanto no backend (Express.js) quanto no frontend (React ou Vue):

🧠 1. Padrão global: Trabalhar com UTC no backend
No backend (Node.js com Express no Replit):

a) Configure o timezone como UTC no Node.js
No arquivo index.js, server.js ou principal:

js
Copiar
Editar
process.env.TZ = 'UTC';
Isso faz com que todos os Date() e funções do Node.js usem UTC como padrão.

b) Armazene datas no Supabase em UTC
O Supabase já usa UTC por padrão, então se o backend estiver mandando datas em UTC, está tudo certo.

Exemplo ao salvar:

js
Copiar
Editar
const data = {
  created_at: new Date().toISOString(), // Isso gera um horário em UTC
};
🌎 2. No frontend: converter UTC para o horário local do Brasil
Se você usa React ou Vue, ao exibir uma data vinda do Supabase (em UTC), converta assim:

a) Usando JavaScript puro:
js
Copiar
Editar
const dataUtc = '2025-07-12T15:00:00Z';
const dataBrasilia = new Date(dataUtc).toLocaleString('pt-BR', {
  timeZone: 'America/Sao_Paulo',
});
console.log(dataBrasilia); // Ex: 12/07/2025 12:00:00
b) Ou usando date-fns-tz (mais robusto):
bash
Copiar
Editar
npm install date-fns date-fns-tz
js
Copiar
Editar
import { format, utcToZonedTime } from 'date-fns-tz';

const utcDate = '2025-07-12T15:00:00Z';
const timeZone = 'America/Sao_Paulo';

const zonedDate = utcToZonedTime(utcDate, timeZone);
const formatted = format(zonedDate, 'dd/MM/yyyy HH:mm:ss', { timeZone });

console.log(formatted); // 12/07/2025 12:00:00
🛑 3. Evite estes erros comuns:
❌ Salvar datas com .toLocaleString() no backend – isso gera datas no fuso local do servidor e pode bagunçar os dados.

❌ Deixar o frontend salvar a hora local no banco – o frontend sempre deve enviar UTC (com new Date().toISOString()).

❌ Confiar no fuso horário do navegador para salvar dados – sempre padronize o backend.

✅ 4. Resumo: padrão ideal
Etapa	Fuso usado	Como fazer
Backend	UTC	new Date().toISOString() e process.env.TZ = 'UTC'
Supabase	UTC	Já é padrão
Frontend	Exibir local	toLocaleString('pt-BR', { timeZone: 'America/Sao_Paulo' })
Frontend	Enviar dados	Sempre com .toISOString()
