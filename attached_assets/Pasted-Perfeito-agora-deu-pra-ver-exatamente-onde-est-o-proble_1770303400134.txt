## 🚨 O QUE ESTÁ QUEBRANDO (CAUSA REAL)

Pelo console da direita dá pra ver 3 sinais claros:

### 1️⃣ **401 Unauthorized**

```
GET /api/vehicles 401 (Unauthorized)
```

➡️ A página de **Cadastro de Veículos** tenta buscar veículos **antes** de ter:

* sessão válida
* base definida
* permissão confirmada

---

### 2️⃣ **AuthContext ainda não carregou**

```
AuthContext Provider values: { user: object, isLoading: true }
```

➡️ O React está tentando renderizar a tela **enquanto `isLoading === true`**

---

### 3️⃣ **Filtro de base não aplicado**

Quando a base (ex: **Coca-Cola**) não vem:

* a query vai sem `base_id`
* o backend bloqueia (correto)
* retorna 401

## ✅ SOLUÇÃO DEFINITIVA (PADRÃO PROFISSIONAL)

Você precisa aplicar **3 correções juntas**.
Se fizer só uma, o erro volta.

---

## 🔧 1️⃣ BLOQUEAR A TELA ATÉ A AUTENTICAÇÃO FINALIZAR

No **ProtectedRoute** ou na página de veículos:

```tsx
const { user, isLoading } = useAuth()

if (isLoading) {
  return <div>Carregando sessão...</div>
}

if (!user) {
  return <Navigate to="/login" />
}
```

📌 **Nunca renderizar a página antes do AuthContext estar pronto**

---

## 🔧 2️⃣ SÓ BUSCAR VEÍCULOS SE TIVER BASE ATIVA

No `useEffect` do cadastro de veículos:

```tsx
useEffect(() => {
  if (!user || !activeBaseId) return

  fetchVehicles()
}, [user, activeBaseId])
```

❌ ERRADO (como está hoje):

```tsx
useEffect(() => {
  fetchVehicles()
}, [])
```

---

## 🔧 3️⃣ GARANTIR QUE TODA QUERY ENVIE `base_id`

No backend (`/api/vehicles`):

```ts
if (!req.user || !req.user.base_id) {
  return res.status(401).json({ error: "Base não definida" })
}
```

E a query:

```ts
SELECT * 
FROM vehicles 
WHERE base_id = $1
```

Nunca:

```sql
SELECT * FROM vehicles
```
